# STE-KO

한국어 기술 문서, 업무 메시지, AI 답변, 커밋 메시지, UI 문구를 위한 통제 언어 규격입니다.

번호가 붙은 작성 규칙 [SPEC.md](SPEC.md)와 비승인 표현 대응표 [dictionary.md](dictionary.md), 두 문서로 되어 있습니다.

## 왜 만들었나

문체 지침은 "쉽게 쓰세요"라고 말합니다. 사람도 AI도 이 말을 지키지 못합니다. 무엇이 어려운지 정하지 않았기 때문입니다.

통제 언어는 다르게 접근합니다. 쓸 수 있는 표현과 쓸 수 없는 표현을 목록으로 정하고, 문장 길이에 숫자를 박고, 규칙마다 번호를 붙입니다. 지켰는지 안 지켰는지 판단이 갈리지 않습니다.

항공기 정비 매뉴얼 규격인 ASD-STE100이 이 방식을 씁니다. 정비공이 문장을 잘못 읽으면 사람이 죽기 때문에, 멋있게 쓸 자유를 규격으로 막았습니다. STE-KO는 같은 방식을 한국어와 네 가지 표면에 적용합니다.

## 실측

STE-KO 없이 쓴 한국어 기술 문서 8개, 17,549어절을 `scripts/lint.py`로 쟀습니다. **위반 55건, 1000어절당 3.1건입니다.**

| 규칙 | 위반 | 비율 |
|---|---|---|
| `1.3` 비승인 어휘 | 28 | 51% |
| `8.1` 범위에 물결표 | 20 | 36% |
| `4.8` 종결어미 3연속 | 6 | 11% |
| `4.1` 어절 상한 초과 | 1 | 2% |

**문장 길이는 문제가 아니었습니다.** 25어절을 넘긴 문장이 17,549어절에서 한 개 나왔습니다. 문체 지침이 가장 자주 말하는 `짧게 쓰세요`가 실제 데이터에서는 걸리지 않습니다. 어휘와 문장부호가 87%를 차지합니다.

물결표 20건은 문체 문제가 아닙니다. 대부분의 마크다운이 홑물결표를 취소선으로 읽어서 문서가 깨지고 빌드가 실패합니다. 읽기 어려움이 아니라 아직 터지지 않은 렌더링 버그입니다.

측정 방법과 한계는 [benchmarks/corpus-2026-08.md](benchmarks/corpus-2026-08.md)에 적었습니다. 코퍼스가 8개이고 한 조직에서 나왔다는 것, 같은 문서의 전후 비교가 아니라는 것, 검사기가 규칙 73개 중 일곱만 본다는 것을 함께 밝힙니다.

## 무엇에 근거하나

STE-KO는 세 갈래 위에 섭니다. 자세한 대응은 [SPEC.md 부록 D](SPEC.md#부록-d-근거와-계보)에 있습니다.

- **한국 공적 자료.** [국어기본법 제14조](https://www.law.go.kr/LSW//lsSideInfoP.do?lsiSeq=270587&joNo=0014&joBrNo=00&docCls=jo&urlMode=lsScJoRltInfoR)는 공공기관이 공문서를 국민이 알기 쉬운 용어와 문장으로 쓰도록 정합니다. 국립국어원은 [한눈에 알아보는 공공언어 바로 쓰기(2022)](https://www.korean.go.kr/front/etcData/etcDataView.do?etc_seq=699)와 [쉬운 공문서 쓰기 길잡이(2022)](https://www.korean.go.kr/front/etcData/etcDataView.do?etc_seq=700)를 펴냈고, 공공언어를 정확성과 소통성 두 영역으로 진단합니다.
- **국제 규격.** [ISO 24495-1:2023](https://www.iso.org/standard/78907.html)은 쉬운 언어의 원칙 네 개를 정합니다. Relevant, Findable, Understandable, Usable입니다. 적용 대상에 기술 문서와 통제 언어를 명시합니다.
- **통제 언어 연구.** Tobias Kuhn의 [A Survey and Classification of Controlled Natural Languages](https://aclanthology.org/J14-1005/) (Computational Linguistics 40:1, 2014)가 통제 자연어 100개를 분류합니다.

**빈 칸이 남습니다.** 공공언어 자료는 한국어를 다루지만 대상이 공문서입니다. 통제 언어 연구가 다룬 100개는 전부 영어 기반입니다. ISO 24495-1은 원칙 층위라 문장 규칙을 주지 않습니다.

한국어 기술 문서를 대상으로 하는 통제 언어 규격은 2026년 8월 검색에서 찾지 못했습니다. 없다고 단정하지는 않습니다. 같은 일을 한 규격을 아시면 알려 주십시오.

## 무엇이 달라지나

규칙을 적용한 예입니다.

> 적용 전
> 배포 관련하여 이슈가 발생되어 확인해 본 결과, 인증 토큰 갱신 실패 처리 로직 부분에서 다소 문제가 있는 것으로 보여지며, 조만간 안정화 작업이 진행될 예정입니다.

> 적용 후
> 배포가 8월 14일 21시에 실패했습니다. 원인은 인증 토큰 갱신 코드입니다. 만료 검사가 `<=`가 아니라 `<`로 되어 있습니다. 8월 16일까지 고치겠습니다.

두 번째 문장이 더 깁니다. 짧게 쓰는 것이 목표가 아니기 때문입니다. 첫 번째 문장은 무엇이 언제 왜 깨졌고 누가 언제까지 고치는지를 하나도 말하지 않습니다.

## 쓰는 법

### 스킬로 설치

에이전트에 스킬로 깔면 규칙을 따로 붙여넣지 않아도 됩니다.

```bash
npx skills add beamonic/ste-ko
```

설치본은 `skills/ste-ko/SKILL.md` 한 장입니다. 표면 네 개, 항상 지키는 열 가지, 버리는 것과 지우지 않는 것, 규격을 자동으로 푸는 조건, 표면별 예문이 들어 있습니다. 규칙 73개 전체는 SKILL.md가 아니라 `SPEC.md`에 둡니다. 매 턴 입력에 실리는 분량을 줄이기 위해서입니다.

`/ste-ko 문서|대화|코딩|UI`로 표면을 바꿉니다. 기본은 `대화`입니다.

### 메모리 파일에 직접 적용

Claude Code나 Codex를 쓴다면 메모리 파일에 한 줄 넣습니다. `~/.claude/CLAUDE.md` 또는 `AGENTS.md`에 적습니다.

```text
- 답변은 STE-KO `대화` 표면을 따른다: 결론 먼저, 한 문장 한 뜻, 25어절 이내,
  능동태, 같은 대상은 항상 같은 단어로 부른다, 이중피동을 쓰지 않는다,
  앞 턴을 되풀이하며 시작하지 않는다, 되묻기는 한 번에 하나.
- 커밋 메시지와 작업 보고는 `코딩` 표면을 따른다: 왜 바꿨는지 쓴다,
  실행하지 않은 검사를 통과했다고 쓰지 않는다.
  https://github.com/beamonic/ste-ko
```

규칙 전체를 지키게 하려면 SPEC.md를 프로젝트에 넣고 경로를 가리킵니다.

```text
- 문서를 쓰거나 고칠 때 docs/ste-ko/SPEC.md 를 읽고 그 규칙을 따른다.
```

### 검사기로 재기

기계로 셀 수 있는 규칙은 `scripts/lint.py`가 잡습니다. 표면을 주면 상한이 바뀝니다.

```bash
python3 scripts/lint.py README.md --surface 문서
python3 scripts/lint.py 'copy/**/*.md' --surface UI
python3 scripts/lint.py --self-test
```

```
README.md:42	4.1	33어절 (상한 25) — 이 문장은 어절을 아주 많이…
README.md:88	3.2	이중피동 `보여집니다`
README.md:91	8.1	범위에 물결표 — 마크다운이 취소선으로 읽는다
```

잡는 규칙은 일곱입니다. `4.1` 어절 상한, `4.7` 문단 문장 수, `4.8` 종결어절 반복, `3.2` 이중피동, `8.1` 물결표, `8.5` 말줄임표, `1.3` 비승인 어휘입니다. `대화` 표면에서는 `10.4` 앞 턴 되풀이도 봅니다. 위반이 있으면 종료 코드 1을 내므로 CI에 그대로 걸 수 있습니다.

`6.1` 결론 먼저나 `2.1` 명사 나열처럼 문맥이나 형태소 분석이 필요한 규칙은 넣지 않았습니다. 오탐이 잦은 검사는 도구를 쓰지 않게 만듭니다. 그 규칙들은 부록 A 점검표로 사람이 봅니다.

### 사람이 쓸 때

[SPEC.md 부록 A](SPEC.md#부록-a-리뷰-점검표)의 점검표를 문서 리뷰에 씁니다. 리뷰 의견은 규칙 번호로 답니다. "이 문장 어색해요" 대신 "2.1 위반, 명사 5개"라고 씁니다. 번호로 지적하면 고칠 방향이 하나로 정해집니다.

## 어디에 쓰나

표면 네 개에 씁니다. 1-8장은 어디서나 같고, 10장이 표면마다 달라지는 부분을 정합니다.

| 표면 | 쓰는 자리 | 표면 고유 규칙 |
|---|---|---|
| `문서` | 기술 문서, Asana 업무 항목, 상태 보고, 절차서, API 문서 | 1-9장 기본 |
| `대화` | AI 답변, Slack 메시지, Asana 댓글, 업무 이메일, 리뷰 코멘트 | 되묻기 하나, 앞말 되풀이 금지, 모르면 먼저 말하기 |
| `코딩` | 커밋 메시지, PR 본문, 에이전트 작업 보고 | 왜 바꿨는지 쓰기, 안 돌린 검사를 돌렸다고 쓰지 않기 |
| `UI` | 버튼, 라벨, 빈 화면, 오류 메시지 | 어절 상한, 사용자 동작을 버튼에 쓰기, 되돌릴 수 없음 표시 |

표면 두 개에는 별도 구현체가 있습니다. 규격이 정하지 않는 것 — 제품이 고를 종결어미, 높임 단계, 표면 고유의 판단 — 을 채웁니다.

| 표면 | 구현체 | 채우는 것 |
|---|---|---|
| `UI` | [ux-writing-ko](https://github.com/beamonic/ux-writing-ko) | 제품 말투, 캐주얼 경어, 긍정형과 그 예외, CTA 예고성 |

구현체는 규칙을 다시 정하지 않습니다. 규칙 번호로 이 규격에 위임하고, 부딪히면 0.3 우선순위를 따릅니다.

쓰지 않습니다: 코드 자체, 로그, 명령어, 법률 문구, 계약서, 인용문, 홍보 문안, 사적인 대화, 소설.

## 출처와 저작권

STE-KO는 **ASD-STE100의 번역이 아닙니다.** 참고한 것과 참고하지 않은 것을 구분해서 적습니다.

**ASD-STE100** (Simplified Technical English)은 ASD(AeroSpace and Defence Industries Association of Europe)의 저작물입니다. 규격 원문, 작성 규칙 문안, 승인 어휘 목록은 저작권 보호를 받으며 이 저장소에 옮기지 않았습니다. STE-KO가 가져온 것은 저작권 대상이 아닌 접근 방식뿐입니다. 규칙에 번호를 붙인다, 어휘를 승인과 비승인으로 나눈다, 문장 길이에 상한을 둔다, 안전 지침을 따로 다룬다는 네 가지입니다.

규칙 본문, 어휘 대응표, 예문은 전부 한국어 문법을 대상으로 새로 썼습니다. 명사 나열 제한(2장), 이중피동 금지(3.2), 번역투 조사 목록(dictionary.md A절)은 영어 규격에 없는 항목입니다. 차이는 [SPEC.md 부록 B](SPEC.md#부록-b-asd-ste100과-다른-점)에 정리했습니다.

ASD-STE100 원문이 필요하면 [asd-ste100.org](https://www.asd-ste100.org/)에서 받습니다.

**caveman** ([JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman), v1.10.0 기준)에서 9장 압축 등급의 착상을 가져왔습니다. 세 가지입니다. 등급을 나눠 압축 강도를 조절한다, 안전 경고에서는 압축을 자동으로 푼다, 부정을 나타내는 말은 절대 지우지 않는다입니다. 규칙 문안은 한국어에 맞춰 새로 썼습니다. 한국어는 부정 표지가 짧아서 세 번째 항목의 위험이 영어보다 큽니다.

caveman의 입력 압축 프록시와 페이로드 타입 감지는 가져오지 않았습니다. 실행 계층이라 문서 규격의 대상이 아닙니다.

같은 조직의 한국어 자산 둘이 이 규격 위에 올라갑니다. 역할이 다르므로 합치지 않습니다.

- **[ux-writing-ko](https://github.com/beamonic/ux-writing-ko)** — `UI` 표면 구현체. 버튼, 오류 메시지, 빈 화면 문구를 쓸 때 씁니다.
- **[no-ai-slop-ko](https://github.com/beamonic/no-ai-slop-ko)** — 표면 무관 편집 도구. 사람이 쓴 초안을 다듬을 때 씁니다.

STE-KO는 사람과 에이전트가 함께 참조하는 규격 문서이고, 둘은 설치해서 쓰는 스킬입니다.

`대화` 표면은 별도 구현체를 두지 않습니다. [plain-korean](https://github.com/beamonic/plain-korean)이 그 자리였으나 12개 항목 중 9개가 이 규격과 겹쳐서 2026-08-16에 STE-KO로 합쳤습니다. 고유했던 답변 분량, 다음 행동, 구조 남용 금지는 규칙 `10.15`, `10.16`, `10.17`이 되었습니다. Claude Code output style 파일은 `skills/ste-ko/assets/claude-output-style.md`로 옮겼습니다.

## 상태

버전 0.4.0. 규칙 73개입니다. 규칙 번호는 유지합니다. 규칙을 없앨 때 번호를 다시 쓰지 않고 `폐기`로 표시합니다.

검사기는 `scripts/lint.py`입니다. 의존성이 없고 표준 라이브러리만 씁니다. 이 저장소의 `README.md`, `SPEC.md`, `dictionary.md`, `SKILL.md`는 위반 0건입니다.

## 기여

어휘 항목을 추가할 때는 [dictionary.md 기여](dictionary.md#기여) 항목을 읽습니다. 사유 없는 항목은 받지 않습니다. "어색해서"는 사유가 아닙니다.

## 저장소 언어 원칙

사람이 읽는 설명과 메타데이터는 한국어로 씁니다. 코드, 명령어, 고정된 기술 식별자, 법적 효력을 보존해야 하는 라이선스 원문은 예외입니다.
